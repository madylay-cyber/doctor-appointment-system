##  Реестр проведенных проверок (Сценарии верификации)

Контроль качества включал в себя сквозную ручную и автоматизированную проверку по 5 функциональным блокам (экранам МИС):

1. **Блок авторизации (Экран 01):**
   - Успешный вход по валидному ОМС (`7824903155670012`).
   - Перехват некорректных форматов (буквы, спецсимволы) регулярным выражением Pydantic на этапе парсинга.
   - Обработка граничных значений длин (короткий ввод из 5 цифр и длинный из 20 цифр).
   - Обработка отсутствующих в СУБД записей ОМС семантическим статус-кодом `404 Not Found`.

2. **Блок фильтрации и поиска (Экран 02):**
   - Выгрузка реестра приёмов клиники многотабличными операторами SQL `JOIN`.
   - Поиск специалистов по текстовой подстроке через оператор `LIKE`.
   - Динамическая фильтрация записей по идентификаторам системных статусов.

3. **Блок создания онлайн-записи (Экран 03):**
   - Резервирование свободного временного слота на будущие даты.
   - Блокировка попыток записи "прошедшим числом" на уровне встроенных валидаторов времени.

4. **Блок управления контактами (Экран 05):**
   - Обновление полей телефона и email авторизованного пациента.
   - Валидация международной маски номера телефона (`^\+7\d{10}$`).
   - Валидация структуры и доменной зоны email-адреса через встроенный тип `EmailStr`.
   - Контроль ограничений пути при передаче невалидных или отрицательных ID пользователей.

5. **Инфраструктурный аудит и отказоустойчивость:**
   - Верификация непрерывного сквозного мониторинга жизнедеятельности веб-сервера и СУБД на эндпоинте `/health`.
   - **Контроль Race Condition (Состояние гонки):** Аппаратное блокирование ядром базы данных попыток параллельного двойного бронирования одного и того же слота времени к одному врачу со статус-кодом `400 Bad Request`.
   - **Контроль персистентности данных:** Проверка каскадного очищения связанных таблиц комментариев (`ON DELETE CASCADE`) при отмене записи администратором, а также контроль сохранения данных на постоянных томах (`Volumes`).
