# \# Система записи пациентов к врачам

# 

# Информационная система для оптимизации рабочих процессов медицинских учреждений и улучшения клиентского опыта пациентов.

# 

# \---

# 

# \# Назначение проекта

# 

# Система предназначена для \*\*полной автоматизации и цифровизации процесса записи пациентов\*\* на прием в медицинское учреждение. 

# 

# \*\*Какие проблемы решает проект:\*\*

# \* Устраняет хаотичную и ручную организацию расписания.

# \* Минимизирует человеческий фактор и ошибки при записи.

# \* Повышает прозрачность доступности врачей в режиме реального времени.

# \* Улучшает качество клиентского сервиса как для пациентов, так и для медицинского персонала клиники.

# 

# \---

# 

# \# Краткое описание функционала

# 

# Архитектура системы включает в себя следующие ключевые модули:

# 

# \* \*\*Онлайн-запись\*\* — пациенты могут самостоятельно выбирать врача, необходимую услугу и свободный временной слот через удобный веб-интерфейс.

# \* \*\*Медицинская карта\*\* — врачи получают доступ к цифровой истории болезни (диагнозы, предыдущие назначения, анализы) еще до начала приема для качественной подготовки.

# \* \*\*Управление расписанием\*\* — администраторы могут гибко управлять сеткой приемов: блокировать слоты на время отпусков, проводить массовые корректировки графиков и контролировать общую загрузку клиники.

# \* \*\*Коммуникации\*\* — автоматическая отправка напоминаний (SMS/Email) для снижения процента неявок, а также встроенный чат для предварительных консультаций между врачом и пациентом.

##  Инструкция по локальному запуску бэкенд-сервера

Проект разработан в рамках слоистой архитектуры на базе асинхронного веб-фреймворка **FastAPI** и реляционной СУБД **SQLite**.

###  1. Подготовка окружения и зависимостей
Убедитесь, что на компьютере установлен Python 3.8+. Установите необходимые пакеты и библиотеки одной командой в терминале (командной строке):
```bash
python -m pip install fastapi uvicorn pydantic email-validator
```

### 🗄 2. Инициализация базы данных
Если файл базы данных `medical.db` отсутствует или его необходимо обновить до исходного тестового состояния (11 заявок, 8 пользователей по ролям, 4 категории), запустите локальную утилиту SQLite:
```bash
./sqlite3.exe medical.db < schema.sql
./sqlite3.exe medical.db < seed.sql
```

###  3. Запуск веб-сервера
Запустите сервер автоматической перезагрузки приложения `Uvicorn` из корневого каталога проекта:
```bash
python -m uvicorn app.main:app --reload
```
*После успешного запуска сервер начнет принимать запросы по адресу `http://127.0.0.1:8000`.*

###  4. Интерактивное тестирование сценариев (Swagger UI)
Перейдите в браузере по ссылке:
 **[http://127.0.0](http://127.0.0)**

Перед вами откроется встроенная интерактивная документация **Swagger UI** со всеми реализованными пользовательскими сценариями (Авторизация по ОМС, Онлайн-запись, Поиск с LIKE-фильтрацией, Карточка приёма и Удаление записи). Каждую функцию можно протестировать вживую с отправкой реальных JSON-пакетов данных в базу.

##  Спецификация модульного API-слоя (REST API)

Бэкенд-сервер предоставляет структурированный REST API-интерфейс, разделенный на независимые изолированные модули с помощью `APIRouter`.

###  1. Локальный запуск и адреса
Убедитесь, что зависимости установлены, и запустите сервер автоматической перезагрузки из корня репозитория:
```bash
python -m uvicorn app.main:app --reload
```
* **Базовый URL локального сервера:** `http://127.0.0.1:8000`
* **Интерактивная документация (Swagger UI):** `http://127.0.0`
* **Спецификация OpenAPI (JSON-схема):** `http://127.0.0`

###  2. Список основных API Endpoints

####  Модуль: Управление Пользователями и Авторизация (`APIRouter`)
* `POST /api/v1/auth/login` — Авторизация пациента в МИС по 16-значному полису ОМС (**Экран 01**).
* `PUT /api/v1/users/{user_id}/contacts` — Обновление email и номера телефона в профиле (**Экран 05**).

####  Модуль: Управление Заявками и Расписанием Врачей (`APIRouter`)
* `GET /api/v1/appointments` — Получение общего реестра приёмов с поддержкой живого поиска по ФИО и фильтрацией через `Query`-параметры (`search`, `status_id`, `category_id`) (**Экран 02**).
* `POST /api/v1/appointments` — Резервирование нового 30-минутного временного слота онлайн-записи с проверкой накладок расписания и защитой от Race Condition (**Экран 03**).
* `DELETE /api/v1/appointments/{appointment_id}` — Безвозвратное удаление/отмена бронирования записи администратором с каскадным очищением чата (**Экран 05**).

###  3. Реальный пример API-запроса и ответа

#### Сценарий: Создание новой заявки онлайн-записи
* **HTTP Метод:** `POST`
* **Полный URL запроса:** `http://127.0.0`
* **Заголовки (Headers):** `Content-Type: application/json`

**Тело HTTP-запроса (JSON Request Body):**
```json
{
  "patient_id": 6,
  "doctor_id": 4,
  "category_id": 4,
  "datetime_slot": "2026-11-08 17:00"
}
```

**Тело успешного HTTP-ответа сервера (`201 Created`):**
```json
{
  "status": "created",
  "appointment_id": 12,
  "datetime_slot": "2026-11-08 17:00"
}
```

**Тело HTTP-ответа при ошибке Race Condition / Двойном бронировании (`409 Conflict`):**
```json
{
  "status": "error",
  "code": "SLOT_ALREADY_BOOKED",
  "message": "Конфликт бронирования: Этот временной слот у врача уже занят другим параллельным запросом.",
  "details": null
}
```
