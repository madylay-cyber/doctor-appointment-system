
Описание ключевых модулей (Спецификация ввода-вывода)

В соответствии со слоистой структурой выделим 4 ключевых компонента системы, которые отвечают за выполнение сквозного сценария ТЗ — «Запись на прием»:

1. AppointmentController (app/appointments/router.py)

• Назначение: Компонент уровня представления (Presentation Layer). Принимает внешний запрос от фронтенда, проверяет валидность структуры JSON-пакета и передает данные дальше в бизнес-логику.
• Входные данные: HTTP POST-запрос с JSON-телом: patient_id (int), doctor_id (int), slot_start_time (string в формате ISO 8601).
• Результат: HTTP-ответ со статусом 201 Created и JSON-объектом созданной записи, либо 400 Bad Request при ошибке валидации.

2. AppointmentService (app/appointments/service.py)

• Назначение: Компонент уровня бизнес-логики (Service Layer). Самый важный модуль. Проверяет, не занят ли временной слот другим пациентом, имеет ли право данный врач оказывать услугу и инициирует отправку напоминания.
• Входные данные: Очищенные параметры от контроллера: patient_id, doctor_id, slot_start_time (datetime объект).
• Результат: Инициализированный объект класса Appointment со статусом Подтверждено, либо исключение SlotConflictError («Врач недоступен в этот день»).

3. StatusService (app/statuses/service.py)

• Назначение: Модуль контроля жизненного цикла заявок. Следит за тем, чтобы статусы менялись строго по правилам ТЗ (например, перевести прием в статус В процессе или Завершен может только Врач, но не Пациент).
• Входные данные: appointment_id (int), current_status (Enum), requested_status (Enum), user_role (string).
• Результат: Логическое подтверждение True при успешной смене статуса, либо исключение InvalidStatusTransition при попытке нелегального перевода (например, из Отменено сразу в Завершен).

4. AppointmentRepository (app/appointments/repository.py)

• Назначение: Компонент уровня доступа к данным (Repository Layer). Изолирует работу с СУБД. Выполняет транзакцию по сохранению брони и запрашивает информацию о загруженности кабинетов для отчетов.
• Входные данные: Объект сущности Appointment для записи.
• Результат: Подтверждение успешной записи строки в базу данных PostgreSQL, либо DatabaseError в случае сбоя соединения.
