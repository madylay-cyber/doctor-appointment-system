
Определение основных модулей системы

В соответствии с техническим заданием проекта, предметная область декомпозирована на 5 функциональных модулей. Каждый модуль проходит сквозь все 4 архитектурных слоя.
lab1-appointment-system/
└── app/
    ├── users/         # Модуль пользователей
    ├── appointments/  # Модуль заявок
    ├── statuses/      # Модуль статусов
    ├── categories/    # Модуль категорий
    └── comments/      # Модуль комментариев

1. Модуль «Пользователи» (Users)

• Назначение: Регистрация, аутентификация и управление учетными записями.
• Ключевые данные: ФИО, телефон, email, полис ОМС (для пациентов), специализация и рабочие часы (для врачей).
• Логика: Первичная регистрация в системе, проверка уникальности ОМС, разделение прав доступа по ролям (Пациент, Врач, Администратор).

2. Модуль «Заявки» (Appointments / Booking)

• Назначение: Автоматизация и координация бронирования временных слотов.
• Ключевые данные: ID пациента, ID врача, дата и время начала/окончания приема, ссылка на кабинет.
• Логика: Автоматический поиск свободных окон, резервирование слота в режиме реального времени, блокирование конфликтующих записей.

3. Модуль «Статусы» (Statuses / Lifecycle)

• Назначение: Управление жизненным циклом и текущим состоянием записей.
• Ключевые данные: Идентификатор состояния (Инициация, Подтверждено, В процессе, Завершено, Заблокировано).
• Логика: Валидация переходов между состояниями (например, перевод в статус «Завершен» возможен только врачом после фиксации осмотра).

4. Модуль «Категории» (Categories / Services)

• Назначение: Ведение медицинских справочников клиники.
• Ключевые данные: Справочник медицинских специальностей, категории заболеваний (коды МКБ-10), перечень доступных услуг и их привязка к врачам.
• Логика: Настройка фильтрации расписания по категориям, закрепление тарифов за конкретными типами приемов.

5. Модуль «Комментарии» (Comments / Consultations)

• Назначение: Внутренние коммуникации и текстовое сопровождение приемов.
• Ключевые данные: Текст обращения, жалобы пациента при записи, предварительные вопросы в чате, медицинские заключения врача в ЭМК.
• Логика: Сохранение истории переписки врача и пациента перед приемом, логирование медицинских примечаний в карту для обеспечения непрерывности лечения.
